# Results

How good the search is, how that is known, and what was tried and rejected.

> Generated by `python -m sextant.eval.results_page --write` from the committed
> measurement files. Do not edit it by hand: a test fails when this page and

## How good is it

On 65 test questions over 21 documents, the shipped pipeline puts the right passage first **93%** of the time. Plain meaning search manages 87%. Each stage below is in the product because this table says it earns its place.

| Stage | right passage first | recall@3 | recall@5 | MRR | nDCG@5 |
| --- | --- | --- | --- | --- | --- |
| Meaning search only | 0.873 | 0.885 | 0.973 | 0.915 | 0.904 |
| Keyword search only | 0.782 | 0.876 | 0.921 | 0.864 | 0.851 |
| Both, fused | 0.909 | 0.921 | 0.973 | 0.950 | 0.931 |
| Both, fused, then re-read (the shipped pipeline) | 0.927 | 0.967 | 0.982 | 0.961 | 0.952 |

Scored on the 55 questions that have an answer. The same four stages on a harder set — 39 questions over one long research paper, 34 with an answer, graded by page:

| Stage | right passage first | recall@3 | recall@5 | MRR | nDCG@5 |
| --- | --- | --- | --- | --- | --- |
| Meaning search only | 0.735 | 0.912 | 0.912 | 0.842 | 0.839 |
| Keyword search only | 0.824 | 0.971 | 0.971 | 0.892 | 0.910 |
| Both, fused | 0.882 | 0.956 | 0.985 | 0.934 | 0.937 |
| Both, fused, then re-read (the shipped pipeline) | 0.912 | 0.956 | 0.985 | 0.947 | 0.953 |

## Knowing when not to answer

A search that always returns something will happily answer a question the
documents cannot. The last stage's score is what lets the system decline.

- Small set: it declines **8 of 10** questions the documents cannot answer, and wrongly declines 3 of 55 that they can.
- Large set: it declines **5 of 5** questions the documents cannot answer, and wrongly declines 1 of 34 that they can.

## What was tried and rejected (9 ideas)

Each had a pass rule written before it ran. None is argued again without a
new fact; the linked note has the method and the full tables.

| Idea | What the measurement said | Note |
| --- | --- | --- |
| A tree of summaries (RAPTOR) | The questions a tree would serve already scored 1.000 hit@5 without one. | [`summary-chunks.md`](../learning/summary-chunks.md) |
| A newer embedding model (bge-small) | Gains 0.091 first-result hit rate on one test set, loses 0.04 on the other; the rule said both. | [`embedder-swap.md`](../learning/embedder-swap.md) |
| Smaller passages (150 tokens instead of 200) | Meaning search alone fell from 0.820 to 0.720 on the handbook set. | [`chunk-size.md`](../learning/chunk-size.md) |
| Dropping the re-reading stage (the reranker) | On the long-paper set it scores 0.000 on every off-topic question; no other stage separates them. | [`reranker-decision.md`](../learning/reranker-decision.md) |
| Letting the model imagine an answer first (HyDE) | Meaning search fell from 0.873 to 0.800, and after re-reading the score was 0.909 either way. | [`hyde.md`](../learning/hyde.md) |
| Prompt caching | A 28% net saving, against the 30% the rule asked for. | [`prompt-caching.md`](../learning/prompt-caching.md) |
| A fallback below the confidence floor, as a cost saving | Across all 55 answerable questions it fired once. | [`floor-fallback-cost.md`](../learning/floor-fallback-cost.md) |
| The same fallback, as a way to find missed answers | The question it was built for scored 0.5 with it and 0.5 without. | [`floor-fallback.md`](../learning/floor-fallback.md) |
| Choosing a different index per question | One index already reaches 0.996 recall in 1.48 ms at 100k passages. | [`ivfpq-100k.md`](../learning/ivfpq-100k.md) |

## What a question costs

**About ₹0.13 a question** ($0.0015): 110 complete answers cost $0.164 in the whole-set run that note records, converted at the note's own rate of ₹84 to the dollar ([`floor-fallback-cost.md`](../learning/floor-fallback-cost.md)). Searching alone costs nothing: the search models run on your machine, and only writing the answer calls a paid model.

## Check it yourself

```bash
sextant-eval
```

That rebuilds the index from the 21 committed documents and prints the first table above. It needs no key and spends nothing. `sextant-eval --check` compares the run against the committed figures and fails on any drop over 0.02; that check runs on every change to the project.

What these numbers do **not** show: the questions and the documents were
written together, so this grades the search pipeline, not how it will do on
someone else's library.
