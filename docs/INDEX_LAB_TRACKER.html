DONE · STEP C Coarse-retrieve → exact-rerank

The pattern production systems ship: IVF-PQ gathers an oversized candidate set cheaply, then exact cosine re-scores only those and keeps the true top-k. Fixes IVF-PQ's recall ceiling while keeping its tiny hot memory.

  • ✓
    RerankIndex — generic wrapper over any base index
    ann/rerank.py — k×oversample candidates → exact re-score → top-k; splits hot (codes) from cold (full vectors)
  • ✓

    green curve on the chart, its own A/B column, honest hot/cold memory note

Synthetic sweep · 2,000 × 128-d · 40 clusters · oversample=8 (cells hold ~31 vectors, so there is a shortlist to reorder)

  • Rerank breaks IVF-PQ's recall ceiling for almost nothing. 0.701 → 1.000 at nprobe=4 for ~0.27 ms extra. Even at nprobe=1 it beats bare IVF-PQ at any nprobe.
  • The memory win survives in the tier that counts. Hot RAM stays the 16-byte PQ codes; the full vectors are a cold disk tier in production, fetched only for the shortlist. The 528 B/vec is this in-RAM harness being honest.
  • On a tiny 52-chunk corpus rerank is a no-op — near-singleton cells, nothing to reorder. It needs multi-vector cells (scale) to help.
✓
Confirmed live at scale. Ingested the arXiv LLM survey (arXiv 2303.18223, ~144 pp → 1,550 chunks; corpus now 1,602). On real embeddings bare IVF-PQ plateaus at recall 0.717; IVF-PQ + rerank climbs to 0.978 — at nprobe=8, 0.707 → 0.937. Exactly the synthetic result, now on real data. (Flat still wins on speed even at 1,602 chunks — 0.055 ms, exact — so the "personal-scale → flat" thesis holds; ANN's turn comes at far larger corpora.)
